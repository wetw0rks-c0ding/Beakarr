# Wizarr Integration (v1 read-only) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Wizarr v3 (URL + API key) as a read-only Beakarr service with Invitations/Users tabs, verified on device.

**Architecture:** Mirror OMV/NPM file-for-file: `WizarrClient` (Dio, Bearer, read-only allowlist), `WizarrService`, Riverpod providers, tolerant models, `SegmentedButton` screen, existing-switch plumbing only.

**Tech Stack:** Flutter, flutter_riverpod, Dio, go_router; no new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-31-wizarr-design.md`

## Global Constraints

- Read-only v1: only list endpoints in the client allowlist; any mutating call throws `StateError` before hitting the network.
- API key lives in secure storage, never in logs (no request-body logger on the auth path).
- Every shell screen reserves the floating-nav-bar bottom inset (`FloatingNavBarMetrics`); the `nav_clearance_test` tripwire must keep passing.
- TDD: failing test first for every behavior; `flutter test`, `flutter analyze` clean before each commit.
- No in-app playback, no invite creation/revocation in v1 (phase 2 has its own gate).
- Version-stamp every build (`GIT_HASH`/`BUILD_TIME`); 0.9.x alpha loop: OCR pre-pass, exactly one CodeRabbit gate, device proof, tag + APK + xcross IPA.

## Review Focus

- Wizarr v3 paginates or envelopes lists differently than assumed (`{data:[...]}` vs bare array) — service must tolerate both shapes, and the test pins both.
- An invite with null/expired `expiresAt` or zero `maxUses` must still render (no crash, sensible "expired/used-up" chip), most likely first.
- A 401 with an HTML login page (wrong URL path) must surface as an error state, not a parse crash.
- API key with surrounding whitespace (pasted on device) must be trimmed before use.
- Empty invitations AND empty users lists each render their own explicit empty state, not a shared blank.
