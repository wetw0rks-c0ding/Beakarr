# 0.9.18-alpha — 2026-11-01

Tag: `v0.9.18-alpha`

Wizarr v3 joins the fleet: read-only guest-onboarding monitor
(invitations + users), device-proven on Pixel 6 against the live
homelab Wizarr (`bertha:5691`, `ghcr.io/wizarrrr/wizarr:latest`).

## Wizarr (new service, read-only v1)

- Settings: Server URL + API Key (`X-API-Key` header — a live probe
  confirmed `Authorization: Bearer` returns `401`, so Bearer is out).
  Test Connection hits `GET /api/invitations` and requires `200`,
  then auto-saves on green.
- Dashboard tile: ONLINE + open-invite count (unexpired with
  remaining uses).
- Invitations tab: code, display name, server chips, uses-left +
  expiry chips, tap-to-copy **absolute** share links (the API returns
  relative `/j/<code>` paths, joined onto the configured URL).
- Users tab: username, email, server, membership expiry.
- `WizarrClient`: in-code read-only allowlist (`StateError` before any
  network call for anything else), no request-body logger on the auth
  path, 401 maps to a clean auth error (live-probed shape
  `{"error": "Unauthorized"}`).
- Models follow the live swagger schemas exactly (`unlimited` boolean
  + `used_at`/`used_by` instead of counters; `status` string;
  `server_names` array) after an initial guess at counter fields was
  corrected against the real payload.
- Out of scope (phase 2, own gate): invite creation/revocation,
  user add/remove.

## Device proof (Pixel 6, live server)

- Test Connection green + auto-saved with the real API key; tile
  ONLINE ("2 invitations").
- Invitations tab matched the server: two live invites (codes redacted —
  see security note below), ACTIVE, display names, server chips,
  ACTIVE, "welcome to piracyhub", "The hub", "1 uses left",
  expiry 2026-11-02, absolute links verified on screen.
- Users tab: "No users" — confirmed accurate via direct API call
  (`{"users": [], "count": 0}`).
- Bad-key path: covered by live 401 probe + unit test (no secret in
  logs); in-app bad-key screen check deferred (would clobber the
  working saved config).
- Settings persistence across restart verified (a missing
  `wizarrUrl`/`wizarrApiKey` load in `loadSettings` dropped the config
  on restart — caught on device, fixed with a round-trip test).

## Security note (CodeRabbit gate)

- The original notes named two live invitation codes. Codes are
  bearer credentials for guest onboarding: both invitations must be
  revoked in Wizarr ("The hub" server) and the test API key rotated,
  since it also appeared in the debug session. Redacting text alone
  does not invalidate them.
- Display names, server chips, and dates above are descriptive only
  and carry no access.

## Notes

- iOS LAN quirk (from 0.9.17 testing): direct `192.168.x.x` URLs fail
  in-app on iPhone (Dio connectionError) while Safari on the same
  phone reaches them; tailnet URLs go green. `NSLocalNetworkUsageDescription`
  is declared (permission shows granted) — folded into this release;
  workaround is tailnet URLs. Fix commit: `8ebf527` range on
  `feature/prowlarr`.
- iOS IPA: xcross-built, arm64/AOT/icons, unsigned for TrollStore
  sideload.
- `release.sh`'s whole-tree `dart format` gate still fails on ~105
  pre-existing drift files; release built with the same defines
  after whole-tree `analyze --fatal-infos` + full suite green, all
  touched files format-clean. Drift cleanup is its own chore.
