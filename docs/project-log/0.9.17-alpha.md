# 0.9.17-alpha — 2026-10-31

Tag: `v0.9.17-alpha`

OpenMediaVault screen renders: the blank-screen root cause was
`OmvUsageBar` used as `OmvStatTile.trailing` — a Row gives non-flex
children unbounded width, the bar's inner `Expanded` throws during
layout, and in release builds that blanks the whole body with zero
logcat errors. Bar moved full-width below the Memory tile (Storage-tab
pattern). Plus: SegmentedButton tabs (NZBGet pattern), SafeArea-aware
top spacer (shell overlay covers `topPadding`-only bodies), memory in
human units ("23.7 GiB / 31.3 GiB").

## Device proof (Pixel 6, live bertha OMV 7.7.24)
- Overview: bertha.local, v7.7.24-7 (Sandworm), kernel
  6.12.85+deb12-amd64, uptime, load, Xeon E5-2637 v2 (4 cores),
  memory + 74–76% bar — all match the server.
- Disks: 6 disks with models, sizes, temps, power mode, Good pills
  (matches tile "6 disks").
- Services: NFS Running, RSync Disabled, SMB Disabled, SSH Running.
- Tab switching Overview/Storage/Disks/Services verified on touch.
- Storage: `FileSystemMgmt.getList` fails server-side (reproducible
  `OpenMediaVaultException: Failed to execute command ...`, same
  params work for DiskMgmt/Smart) — surfaced via the error state,
  not silently dropped. Documented known issue; user checks bertha.
