# 0.9.19-alpha — 2026-11-01

Tag: `v0.9.19-alpha`

Patch release: two updater defects found while verifying 0.9.18 on
device, plus the version-label drift that hid them.

## Updater fixes

- `releasesUrl` pointed at the pre-rename upstream
  `wetw0rks-c0ding/seekarr` path (only worked via GitHub's rename
  redirect); now queries `beakarr` directly. Same for the two
  releases-page links in Settings.
- Asset matching looked for a `-android.apk` / `-ios.ipa` infix, but
  release artifacts are named `beakarr-<version>.apk/.ipa` — every
  update check ended in "No update asset found". Now matches the
  extension. Verified end-to-end on Pixel 6: check → found
  0.9.18-alpha → downloaded 64 MB → system installer.
- `kAppVersion` (which the update check compares against) was still
  `0.9.16-alpha` after the 0.9.18 bump, so installed 0.9.18 builds
  would be re-offered 0.9.18 forever. Bumped with the release, and a
  new `app_version_test` pins the constant to pubspec so it can't
  drift again.

## Notes

- Debug split-per-ABI builds carry inflated versionCodes (e.g.
  2019) that block release installs (19) as "downgrades" — dev-device
  only; `adb install -r -d` still works and preserves data. Release
  users (monotonic 18 → 19 → 20) are unaffected.
- iOS IPA: xcross-built, arm64/AOT/icons, unsigned for TrollStore
  sideload.
