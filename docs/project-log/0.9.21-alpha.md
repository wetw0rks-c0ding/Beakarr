Wizarr invite revocation: close the guest-onboarding lifecycle from
the app, device-proven against live bertha Wizarr v3. Plus the
CodeRabbit-gated dialog fix.

## Invite revocation (new, gated mutating path)

- Every invitation tile gains a revoke icon-button (tooltip
  `Revoke`, hidden when `id == null`); tapping opens a confirm
  `AlertDialog` ("Revoke invite CODE? … Guests with the link will
  no longer be able to join.").
- Confirm runs `DELETE /api/invitations/{id}` (exact literal path,
  never the fuzzy GET-only resolver) with the `X-API-Key` header and
  the standard 10/10/15 s timeouts. 2xx (object or empty body) =
  success; 401/404/HTML/transport surface verbatim in the dialog.
- The client allowlist gains exactly one sibling set
  (`_deleteOnly = {'Invitation.delete'}`, same per-verb pattern as
  `_createOnly`); every other non-list call still throws `StateError`
  before any network I/O. No generic DELETE passthrough exists.
- Success invalidates `wizarrInvitationsProvider` (row disappears,
  home tile count drops) + snackbar; errors change no state.
- The dialog is a `ConsumerStatefulWidget` with a `_submitting` flag
  (both buttons disabled + spinner in flight); barrier tap and
  system back are blocked while submitting so an accidental
  dismissal can't skip list invalidation (CodeRabbit gate find,
  fixed + test-pinned).
